# 研究路线图

本文档回答老师提出的三个问题，并把"系统优化"与"安全"两个阶段拆成可以逐条落地的任务，
每条任务都标注了对应的代码位置。

---

## 0. 当前进度

已完成（本仓库）：

- 可运行的 **baseline prototype**：车辆跨 cell 移动 -> handover -> 服务在边缘节点间迁移。
- 四种迁移策略：`reactive`（基线）、`reactive_delta`、`proactive`、`proactive_delta`。
- 三类指标：连续性、迁移成本、**可观测侧信道**（安全阶段的输入）。
- "策略 x 车速"扫描 + 出图 + 自检脚本。
- 拓扑/移动/服务三个维度都可替换：规则网格或真实基站站点，合成轨迹或 Rome/SF 出租车轨迹，
  四类 MEC 服务的参数集中在 `services/catalog.py`。

已验证的核心现象（`results/sweep/sweep_summary.csv`）：

- 中断比例随车速显著恶化：baseline 从 9.7%（15 km/h）升到 56.2%（90 km/h）。
- 增量状态把迁移字节与开销比降低约一个数量级。
- pre-copy 把中断压到个位数百分比，但字节成本不变 —— 形成明确的 Pareto 前沿。

## 1. 系统优化：三个方向

### 1.1 迁移策略（何时迁、迁到哪里、迁谁）

**现状**

- 时机：`reactive`（切换后）vs `proactive`（前视 `lookahead_steps` 步，理想预测）。
- 目标节点：固定为"当前/下一 cell 的边缘服务器"（`_target_coordinates` + `_server_at`）。
- 对象：一辆车的四个服务全部迁移。

1. **轨迹预测器替换理想前视**
   在 `migration/controller.py::_target_coordinates` 中接入预测模块（一阶马尔可夫 / 路网最短路 /
   GRU），并增加配置项 `migration.predictor`。实验上扫描"预测准确率 - 连续性"曲线：
   预测错一次就多一次无效迁移，这条曲线本身就是论文的一张图。
2. **目标节点选择不再固定为地理最近**
   现在是"谁近迁给谁"。可加入负载与带宽感知：在 `_select_migrations` 中按
   `free_cpu/free_mem/link_residual_delay` 打分。EdgeSimPy 已经提供
   `EdgeServer.has_capacity_to_host()` 与链路 `bandwidth_demand`。
3. **服务级差异化策略**
   四类服务状态大小差两个数量级（3 MB vs 200 MB）。可以让"小状态、低收益"的服务直接
   远程访问（不迁移），只迁移"重状态"服务。实现：在 `_select_migrations` 中按
   `profile.state_mb` 与"迁移成本 / 远程访问惩罚"做决策，配置项 `migration.policy_per_service`。
4. **批量与合并迁移**
   多辆车同向移动时把多次迁移合并成一个批量任务，降低控制面开销。可在控制器里维护
   "待迁移队列"，每 N 步统一提交一次（`migration.batch_interval`）。
5. **切换与迁移解耦（双连接/多归属）**
   车辆短暂同时连接两个节点，状态在新旧节点共存一段时间，消除刚性切换。

### 1.2 迁移底层优化（怎么把一次迁移做快、做便宜）

**现状**

- 镜像按层缓存（EdgeSimPy container registry），只有未缓存层会传输。
- 状态支持"全量 / 增量"两种传输量。

1. **增量粒度细化**：目前增量 = `增长率 x 距上次同步的步数`。可改为按"脏页/脏块"建模，
   加入 `migration.delta_model: {linear, chunked, compressed}`，并加入压缩比参数。

## 2. 安全阶段：从侧信道到轨迹推断

### 2.1 威胁模型

攻击者 = **外部被动观测者**（例如运营商之间的中间网络、被攻陷的交换机/链路监听点）。
它能观测到：

- 迁移**发生的时间**，
- 迁移的**源节点与目标节点**，
- （可能）迁移的**字节数**与持续时间。

它**不能**：解密迁移内容、看到车辆标识、看到应用层数据（这些都是防御的目标）。
攻击目标：由迁移序列推断车辆的移动轨迹 / 下一个 cell / 用户身份关联。

### 2.2 攻击者观测面（已经准备好）

每次运行都会输出 `observable_migration_trace.json`：

```json
[{"step": 132, "source_node": 7, "target_node": 13, "bytes": 210.4}, ...]
```

对照真值 `handovers.csv`（`step, vehicle_id, source_cell, target_cell`）。
迁移事件与握手事件天然一一对应，因此**baseline 相当于一个"明文广播轨迹"的系统**——
这正是要修的问题。

### 2.3 攻击实现与评估

1. **朴素攻击**：把迁移序列直接当作轨迹（当前 baseline 下准确率接近 100%），
   作为攻击上界。
2. **关联攻击**：用 (时间差, 节点对) 建图，做序列匹配/匈牙利算法，把事件聚类成"车辆"。
3. **推断攻击**：训练一个分类器（逻辑回归 / HMM / 序列模型），输入迁移事件序列，
   预测真实轨迹或下一个 cell。
4. **评估指标**：
   - 轨迹重构准确率 / 位置误差（Top-k cell 命中率），
   - 车辆身份关联准确率（正确聚类的比例，可用 F1），
   - 迁移可检测性（攻击者能否区分"有迁移"和"无迁移/伪装迁移"），
   - 推断所需的最少观测事件数。

### 2.4 防御族与实现钩子

| 防御 | 直觉 | 实现钩子 |
|---|---|---|
| 时序混淆 | 把迁移推迟到随机时刻，破坏"迁移时刻 ≈ 握手时刻"的耦合 | 控制器里给 `_start_migration` 加 `jitter`（以步为单位），配置项 `security.timing_jitter` |
| 诱饵迁移 | 在不移动的车辆上发起假迁移，稀释真实信号 | 控制器里周期性对随机 (服务, 目标) 调 `provision()`，用 `security.dummy_rate` 控制比例 |
| 路径填充 | 让迁移路径绕行/合并，隐藏"源-目标"真实相邻关系 | 迁移时把 `path` 换成非最短路径（`NetworkFlow` 的 `path` 参数），或经中继节点转发 |
| 批量/聚合 | 多个迁移同时发生，攻击者无法一一对应 | 与 1.1 的"批量迁移"共用实现，加 `security.batching` |
| 状态无关填充 | 迁移字节数固定/加噪，隐藏状态大小这一辅助特征 | `security.padding_mb`：在 `service.state` 上叠加随机填充 |
| 加密隧道 | 内容层保护（本工作聚焦元数据层，可作为对照实现） | 与路由/填充正交 |

**重要**：防御会引入额外开销（更多字节、更长迁移、更多中断），因此安全阶段的评估必须复用
第一阶段的三类指标，报告"**安全性 - 连续性 - 成本**"三维权衡。

### 2.5 安全指标

- 轨迹推断准确率 / 位置误差（攻击者视角，越低越好）
- 迁移事件的可区分度（AUC / KL 散度，接近随机最好）
- 防御开销：额外字节、额外中断步数、额外时延（相对 baseline 的百分比）
- 安全 - 开销比：每降低 1% 推断准确率所付出的开销

### 2.6 代码落地方式

建议新增一层"安全包装"，不改动已验证的迁移逻辑：

```
myedgesimpy/security/
  threat.py        # 攻击者模型：从 observable_trace 生成观测
  attacks.py       # 朴素 / 关联 / 推断攻击
  defenses.py      # 时序抖动、诱饵、填充、批量（以策略装饰器形式挂在控制器外）
  evaluation.py    # 安全指标与图表
```

控制器已经具备两个接口点：

- `MigrationController._start_migration()`：插入抖动/填充/诱饵；
- `MetricsCollector.observable_trace()`：攻击者的输入，直接喂给 `attacks.py`。

## 3. 数据集与实验矩阵

| 维度 | 取值 |
|---|---|
| 移动数据集 | Rome、San Francisco（真实出租车轨迹）；合成轨迹作为对照 |

| 策略 | reactive、reactive_delta、proactive、proactive_delta（+ 后续安全变体） |
| 服务集合 | 导航、信息娱乐、上下文告警、实时交通分析（可单独开关） |
| 关键指标 | 中断比例、迁移时延（均值/P95）、迁移字节、开销比、SLA 违约率 |
| 重复次数 | 每配置 >= 5 个随机种子，报告均值与 95% 置信区间 |

运行方式：

```bash
python -m myedgesimpy sweep --config configs/default.yaml \
    --speeds 15,30,45,60,90 \
    --strategies reactive,reactive_delta,proactive,proactive_delta \
    --out results/sweep
```

## 4. 论文叙事建议

1. **问题**：MEC 中车辆高速移动导致服务状态必须在边缘节点间频繁迁移；朴素迁移的
   中断与开销都不可接受（用本文 baseline 曲线量化）。
2. **贡献一（系统）**：一个可复现的、覆盖真实移动/网络/服务负载的迁移仿真框架，
   给出"车速 - 中断 - 开销"的基本规律（当前结果已可支撑）。
3. **贡献二（优化）**：预测式 + 增量 + pre-copy 的组合如何把中断从 ~56% 压到 ~7%，
   并给出 Pareto 前沿（当前结果已可支撑）。
4. **贡献三（安全）**：迁移元数据本身是轨迹侧信道；给出攻击评估方法与防御族，
   报告安全-连续性-成本三维权衡（第二阶段）。
